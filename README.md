### 1. Описание функциональности монолитного приложения

**Управление отоплением:**

- Пользователи могут удалённо включать и выключать отопление в своих домах через веб-интерфейс.

**Мониторинг температуры:**

- Система получает текущие показания температуры от датчиков.
- Пользователи могут просматривать текущую температуру через веб-интерфейс.

**Ограничения текущей функциональности:**

- Самостоятельное подключение устройств пользователями не предусмотрено: требуется выезд специалиста.
- Управление освещением, воротами и видеонаблюдением, а также настройка пользовательских сценариев автоматизации не входят в описанную функциональность текущего решения.

**Примечание:** предоставленный код реализует только операции с датчиками и получение температуры; управление отоплением и веб-интерфейс отсутствуют.

### 2. Анализ архитектуры монолитного приложения

- **Язык программирования:** Go.
- **База данных:** PostgreSQL.
- **Архитектура:** монолитная; HTTP-обработчики, модели, доступ к БД и клиент API в одном приложении.
- **Взаимодействие:** синхронные запросы к БД и API температуры
- **Масштабируемость:** приложение масштабируется целиком
- **Развёртывание:** Компоненты монолита развёртываются совместно. Docker Compose объявляет `app`, `postgres` и `temperature-api`.

### **4. Проблемы монолитного решения**

- Функциональные модули нельзя независимо развёртывать и масштабировать.
- Ошибка в одном модуле может повлиять на работу всего приложения.
- Добавление новых типов устройств требует изменения и повторного развёртывания общего приложения.
- Синхронные обращения к устройствам задерживают ответы; в предоставленном коде время получения списка растёт из-за последовательного опроса датчиков.

Последняя проблема связана с текущей реализацией взаимодействия, а не с монолитной архитектурой как таковой.

# Задание 5. Работа с docker и docker-compose

Перейдите в apps.

Там находится приложение-монолит для работы с датчиками температуры. В README.md описано как запустить решение.

Вам нужно:

1) сделать простое приложение temperature-api на любом удобном для вас языке программирования, которое при запросе /temperature?location= будет отдавать рандомное значение температуры.

Locations - название комнаты, sensorId - идентификатор названия комнаты

```
	// If no location is provided, use a default based on sensor ID
	if location == "" {
		switch sensorID {
		case "1":
			location = "Living Room"
		case "2":
			location = "Bedroom"
		case "3":
			location = "Kitchen"
		default:
			location = "Unknown"
		}
	}

	// If no sensor ID is provided, generate one based on location
	if sensorID == "" {
		switch location {
		case "Living Room":
			sensorID = "1"
		case "Bedroom":
			sensorID = "2"
		case "Kitchen":
			sensorID = "3"
		default:
			sensorID = "0"
		}
	}
```

2) Приложение следует упаковать в Docker и добавить в docker-compose. Порт по умолчанию должен быть 8081

3) Кроме того для smart_home приложения требуется база данных - добавьте в docker-compose файл настройки для запуска postgres с указанием скрипта инициализации ./smart_home/init.sql

Для проверки можно использовать Postman коллекцию smarthome-api.postman_collection.json и вызвать:

- Create Sensor
- Get All Sensors

Должно при каждом вызове отображаться разное значение температуры

Ревьюер будет проверять точно так же.
